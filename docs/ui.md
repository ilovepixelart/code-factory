# UI principles

What the board and the timeline follow, and why. Each rule comes from a measured failure
in the field or from a convention that every credible supervisor interface shares.

## The board

The board, ticket list and ticket detail use one delivery status line. It names the active agent
and stage, or the current wait or retry. The age uses the original event time and one shared
browser clock. The ticket detail announces status changes without moving keyboard focus, and links
to the run, pull request and check evidence when those records exist.

To look at a page while changing it, serve the demo board (`sh scripts/demo.sh`, port 4321): every
page has data on it there ([quickstart.md](quickstart.md#sample-boards)).

| Rule | Reason |
|---|---|
| Group by who must act, not by what the agent is doing | The first question of a person supervising several agents is "does anything need me". Blocked sessions come first, ordered by how long they have waited |
| One activity sentence per row: the current tool call with its short summary, or the last prompt | Raw payloads are unreadable in a row. A row is a label, the detail is one click away |
| Age is the time since the last event, and it freezes when the session ends | A ticking age on a finished session reads as activity |
| Stale is its own state, distinct from idle, listed after the live sessions; a working or idle session, or a subagent, with no event for an hour (`sessions::ENDED_AFTER_SECONDS`) has ended (CF-1193) | A working session that has gone quiet for longer than the threshold may have crashed; idle is a session waiting for a prompt. A session that ends without its `SessionEnd` or `Stop` would read as working forever |
| A row is compact (CF-1204): state, its ticket (else `<repository> on <branch>`), the open tool call or last prompt, age and cost, the tool line and subagents under an expander (a subagent that stopped counts as finished and draws no tool call; one running with a call open and no event for 600 s reads `stale` and draws none, CF-1281); Waiting on you are cards, longest wait first, each with Open session (the first one `btn-primary`), and the rest filter by state (`All`, `waiting`, `working`, `idle`, `stale`, `?state=` in the address, counted over the rows the page reads) | The branch is what people recognise a piece of work by; five rows of the same badges and a wide tool line read as a log, not an overview |
| A session belongs to a ticket only through its worktree (`.code-factory/worktrees/<ID>`) or a branch that is not the repository's default branch, so a session on `main` is on no ticket that declares `main` (CF-1204) | A ticket naming `main` put every session on main under it |
| The tab title names the page (`(6) Tickets · code-factory`, the route's title; a ticket or a session, whose route has none, is named by its id, `(6) CF-12 · code-factory`), and it and the sidebar's Inbox link carry the count of what waits on you: a default branch failing its own run (CF-1251), open agent questions, permission requests, screens to approve, waiting sessions, stopped agents (a run refused because agents are stopped only until they resume; with them a queued ticket whose start was refused: its model's connection giving no answer, refusing, not listing the model or holding it with too little context, or any other refusal of the start; it reads `not started: <refusal>`, the words its card's queue line carries, until a start goes through, CF-1214, CF-1273), failing checks and pull requests ready to merge (`inbox::REPLIES`); a stopped agent or a failing check on a ticket that also has a question, a screen, a pull request ready to merge or a memory proposal is hidden, and listed again once that item is gone (CF-1299); the review queue is listed but not counted, each ticket with its age since it reached Review, the earliest of its branch's first appearance on the remote (the main repository's reflog of `origin/<branch>`), its pull request's opening and its recorded move (CF-418), none when no start is recorded (those lead the queue in board order, CF-412); an item of any other section whose moment cannot be read shows no age either and leads its section (CF-419) | The board is usually a background tab; a queue that is always long would make the count mean nothing |
| Attention is cleared by a state change in the ledger, never by opening the page | "Seen" is not "handled". A dismissed attention item is the most common way tools lose work |
| Ended sessions are hidden by default, one toggle away | They pile up within a day and bury the live ones |
| Blocked sessions is whole; the rest come a page at a time (50, `page` and `size` in the address), grouped by repository in the server's order (`GET /api/sessions?page&size`, `ended=1` with Show ended); the state chip is `state` in the address and the request, applied before paging, and the chips and the repository headings read the answer's `counts` and `repositories` (over every page); costs fill in after the list shows | Drawing over a thousand rows held the page for a second, and the whole list was read at every poll; usage reads every changed transcript, seconds after a deploy; chips counted the page's rows only (CF-1086, CF-1194, CF-1265) |

## The timeline

| Rule | Reason |
|---|---|
| Entries are grouped into turns, one per prompt | A turn is the unit a person reasons about |
| The latest turn and any turn holding a failed or denied call are open; the rest are collapsed | Collapse by default, expand on signal. A long session stays readable |
| A turn reads running only while it is the latest and has not ended, and `stale` instead while its session is stale (so does a call left open, and the session's state reads Stale as on the Sessions list); otherwise done, with its failed or denied calls counted beside its calls, and its length spans its first to its last entry (CF-1227) | A prompt sent mid-turn starts a turn whose predecessor never sees its own end, and one failed call does not fail a turn that ended |
| A turn the person opened stays open across live refreshes | The page must never undo a choice the person just made |
| One row per tool call: an icon for its kind (file, pencil, terminal, search, bot, link, wrench), label (type plus short summary), status, own duration, and its bar | The row set every trace viewer converges on. Waiting is distinct from running, denied from failed |
| A bar on each turn's own time axis: it starts at the call's offset from the turn's first entry and is as wide as its share of the axis (the turn's first entry to the end of its last call, shown as `0s` and its length above the rows); the empty track before it is the wait (CF-1384; `web/src/lib/trace.ts`) | Where a turn's time went reads at a glance, not from the clocks of the rows either side |
| A gap of more than one minute between a row and everything before it is a line of its own, `3m idle` | An agent waiting on a check or the owner is not shown by any row |
| A failed or denied call marks its whole row with the error border and tint, a cross (a ban for denied) and the word in its badge; its bar is the error colour; bars and markers keep 3:1 and their words 4.5:1 in both themes | Status is never colour alone (WCAG 1.4.1, 1.4.11) |
| Subagent work is nested under one collapsible row naming the subagent, with its calls, failures, the sum of its calls' durations and its own bar; it opens while one of its calls failed | Parallel work must be attributable, and a failure must not hide in a closed group |
| A call is one row of seven columns while the Timeline is 56rem wide or more, measured on the Timeline itself (`@container`, `@4xl`), not the window; narrower, its icon and words lead the row and its time, status, length and bar wrap under them, under a narrower rail (`TraceRows.vue`) | Beside the sidebar at 768 to 1279 px the seven columns left a call no width for its words and ran out of the card |
| Full inputs and outputs appear only on request | Dumping payloads into rows is the failure mode of raw span viewers |
| A session the board does not hold reads `Session not found` in the header and `No session <id>` with a Sessions button; a first read that fails names the session (`Session <short id>`) beside its failure and Read again | A heading left at `Loading…` beside an answer said the page was still reading, and offered no way on |
| The page holds the latest 500 entries; Show earlier asks for 500 more, and turns keep their numbers | A long session's whole timeline is tens of megabytes, asked for again at every poll (CF-1066) |

## The kanban

| Rule | Reason |
|---|---|
| Columns are the stages of the process, and a card sits in the first stage whose evidence is missing | Nobody drags a card. The board cannot disagree with the repository |
| The Merged column lists its cards newest first (by id) and shows the 10 newest, then `Show N more`, pressed to list them all (`Show fewer`); its count stays the whole total (CF-1077) | The board is for work in flight; 600 merged cards buried it |
| The ticket list leaves out a column every shown row leaves empty (Assignee) or fills with one value (Repository) (CF-1079) | A column of nothing pushes the useful ones apart |
| A ticket before Build shows no checks row when its repository has no checks command; from Build on it says how to add one; the stage property left to the evidence reads `<Stage> (auto)`, and the New ticket form offers no Stage, a new ticket starting in Spec (CF-1081, CF-1089, CF-1201) | A warning on every Spec ticket about checks that only run at Build is noise |
| The New ticket form and the ticket's edit form list their properties in one set of groups, order and words (`ticket/PropertyGroups.vue`): Planning (Repository in the form only, Stage in the edit only, Type, Priority, Due, Assignee, Labels, Blocked), Relations (Parent, Blocked by, Caused by on a bug; the ticket's Links section is the other place links show), Code (Branch, Pages, and folded under "Tests and parallel", which opens while one is set: E2E tests, Unit tests, Parallel), Agent (Budget), Origin (Source, typed in the form and read only after); New ticket is a `Dialog` (a focused task that takes input) showing Title, Description, then Repository (the one the last ticket went to, kept per browser, else the first listed), Type, Priority and Labels side by side, and folds the rest of the groups under "More properties", which opens while one of them holds a value; a created ticket's notice offers Open CF-n and its card is scrolled into view; a value the board refuses shows its reason under its field in the edit (a `FieldError` the field names in `aria-describedby`, the field marked `aria-invalid`) and below the description in the form, the typed text kept (CF-1201); the form closed by Escape, a click outside or Close and opened again for the same preset (a plain open, or a child of the same ticket) keeps its text, and Create and Cancel clear it, a different preset starting blank; Create and Duplicate announce the id the board gave (`Created CF-5`, `Duplicated CF-3 as CF-6`); Labels is a tags input and Due a date picker, each saving as a tag is added or removed and as a day is picked or cleared; every field of every form is built from shadcn-vue's Field family (docs/design.md, Form fields) | Two lists in two orders and words made one field hard to find in the other, and a refusal that showed only in a passing notice was gone before it was read |
| A card shows id, type, title, its repository (only while the board tracks more than one, CF-1076), branch, and the sessions on it with their state (not those that ended, CF-1076); its due date as `overdue 10 Oct` or `soon 12 Nov`; no line restating its column, which git decides (CF-1205: Spec has no branch yet, Build is on a branch, Review has its pull request open, each column's header saying so), and a stopped run's reason once (`Stopped at its cap: flint 3,000,233 of 3,000,000 tokens`); a ticket whose latest run ended on its runtime's usage limit shows `Usage limit: resumes in <time>`, or `Usage limit: resuming` once due (CF-395) | The fields every board shows, plus the one thing only ours can: who is working on it right now; a ticket waiting on a limit reads as waiting, not failed |
| A ticket's page has a Preview section only while `[preview] command` is set (CF-1379): Preview, or while it runs Open preview (a link to its port on the loopback name other than the board's canonical one, `address` from the route, so the board's cookie is never sent to it (CF-1426, CF-1438), a new tab), the address and Stop; the page reads its state every 5 seconds, as the board stops it on a merge and after `[preview] idle_seconds` (`TicketPreview`, `GET`/`POST`/`DELETE /api/tickets/{repository}/{id}/preview`) | A button for a command nobody configured is a dead end, and a preview the board stopped must not keep a link to a closed port |
| Folders the board could not read are listed under it, with the reason | A silently skipped ticket is a lost ticket |
| The board updates live: a page that shows it (Tickets, a ticket, Sessions, a session) reads `/api/board` every 3 seconds with its ETag while the tab is seen; every other page reads it as the app opens, after a change and as the command menu opens, and every page reads it again each 3 seconds until it first answers (`web/src/lib/live.ts`, CF-1235). The server keeps its last answer and gives it again, building nothing, while every file, folder and git checkout that answer was built from and the sessions it reads are as they were, 15 seconds at most by the board's clock (CF-1238). A change of a ticket's evidence, which the ticket's times in its stages are read from, is recorded once, stamped with the board's clock, by whichever sees it first: the follower's pass (when what it reads changes, and every 30 seconds at least), with no page open at all, or a read of `/api/board` that builds the board (CF-1239) | Cards move within seconds of their evidence, a page that does not show the board does not poll it, and an idle board costs next to nothing; what the clock alone moves (a claim running out, a card's days in its column) shows at most 15 seconds late |
| A page's own polled reads (Sessions and a session, Team, Agents, the Inbox list, a ticket while it has runs, a preview) poll only while the tab is seen and read again as it shows (`usePolledRead`, `web/src/lib/queries.ts`); only the Inbox count polls in a hidden tab, since it fires the desktop notifications | A tab left open in the background costs no requests, and what it shows is fresh the moment it is looked at again |
| The first Tab stop is `Skip to content`, shown only while focused, which moves focus to the page area (`<main id="content">`); the sidebar's brand, quick actions, pages and foot sit in an `aside` named Sidebar (`components/AppSidebar.vue`) | Eleven stops of sidebar stood before every page, and the brand sat outside every landmark (WCAG 2.4.1) |
| On a phone the header grows when a page's controls wrap, so the shell keeps its header and page area unpainted until the first page has mounted and its title and controls are in the header (`App.vue`, `e2e_on_a_phone_*_loads_without_the_page_jumping`); later navigations keep it shown | A page that jumps as it appears moves what a person is about to press |
| Until the board's first answer the page reads "Loading the board" and draws no column (`e2e_the_board_shows_loading_until_its_first_answer`); a read that fails before any answer says why with Read again (`ReadState`), and one that fails later keeps the cards | A blank or empty board reads as broken while the first answer is on its way (CF-445), and a board that never answers must not read as loading for ever |
| While the board refuses the shell's read with 403 (a browser without the owner's sign-in), every page gives way to `This browser is not signed in`, the board's reason with its first letter capitalised, without a trailing `: run uv run code-factory open` the next line already says (a refusal carries nothing that tells a sign-in refusal from another 403, so the instruction is always shown) and `Run uv run code-factory open to sign in your default browser, or open the link uv run code-factory sign-in prints in this browser within 60 seconds.`; meanwhile the header reads `Sign in` and `signed out` with no status dot, not the page's name or `connecting`, and the card sits on the page's own background; the next answered read brings the page back (`SignInNotice`, CF-1178, CF-1181) | Every read is refused without the cookie, so a page left to itself drew an empty body with no word of why |
| The header reads `reconnecting` while any read the page holds (its own, the board's or the Inbox count) got no answer from the board at its latest try, and under it `The board did not answer; this page shows its last read, from HH:MM.` while such a read keeps an earlier answer on the page; a refusal with the board's reason is an answer and leaves `live` (`useUnanswered` in `web/src/lib/queries.ts`) | Only the board's read told the header, which a page that does not show the board does not poll: Inbox, Team, Memory, Analytics, Archive and Agents kept `live` and old figures with no word while the server was gone |
| Updates wait while a card is dragged, then land in one refresh | Nothing moves under the pointer |
| The board spans the full width: columns share it equally from a 256 px floor, run the full height, each scrolls on its own, and the board scrolls sideways once they no longer fit | Nine columns never fit a laptop, and a wide screen should not waste space around a centered board |
| A column is shadcn-vue's `Card`; its cards scroll in a `ScrollArea` whose bar overlays the cards, so they keep one width, and shows only while the pointer is over it or it scrolls (`web/src/components/BoardColumn.vue`) | The owner's decision: a default bar 15 px wide behind 8 px of padding took width from the cards and showed on every column all the time |
| A column is folded when it is empty and open when it has cards; a manual fold or open is remembered per browser until the column's card count crosses zero | Room for the columns with work; columns follow their cards as agents move them |
| A card carries a type dot, a muted id, a medium title, one row of chips and a footer with repository and branch; depth comes from a hairline border, never a fill or a heavy shadow | The anatomy the popular boards converge on; whole-card fills and stripes read as dated |
| Labels are outlined pills with a colored dot, one stable color per label name | Color stays a small token; the same label looks the same on every card |
| A card groups its data: a quiet header (id, type, then the priority mark against the card's right edge, hidden while the card's actions button shows there), the title, labels, one icon row (due, `Checklist 0/3`, `Child tickets 1/2`, `3 days in Build` or `In Build since today`, `Git shows Review` when git puts it in another column), then a footer with repository, branch and assignee; an open question shows once, as its badge, with no status line restating it; each label's dot keeps a faint ring (`ColorDot`), so the darkest and lightest chart colours stay visible in both themes | Dense data stays readable when each group has its own line and weight; a fact said twice, or in the board's shorthand, reads as noise |
| A pull request's size, as GitHub counts it, shows beside its link on the card, in the ticket's status line and on an Inbox merge item (its `size`): `+<added> −<removed>` (`components/PullSize.vue`), its title naming the lines and files, and a warning `Large` badge past 400 changed lines (`LARGE_PULL_LINES`, `lib/pullSize.ts`); a pull request read without a count shows none. Delivery reads `additions`, `deletions` and `changedFiles` with the rest of the pull request | Writing a change costs ever less while reading it does not: the size says what a review will ask before it starts, and past 400 lines a review stops catching defects well |
| A card opens in a side panel: its title and, under it, where it stands, open questions, description, agent, checks, activity, then documents, screens and links (CF-1206); quiet property rows on the right, each a label and its value (an empty one in muted words saying what empty means) that, pressed, shows its own control opened in place (a select its list, a date its calendar) until the focus leaves it or Escape, and stays open while the board refuses its value (`PropertyShown.vue`); the activity shows each run as one row (agent, model, its column, its outcome as a status badge, duration and tokens, a Log button, the age at the right) and every other entry as one sentence in plain words with its age at the right (CF-1075) | The board stays visible, and the process reads at a glance before the details |
| A session subagent whose newest tool call naming a worktree names `.code-factory/worktrees/<ID>` shows on ticket `<ID>`'s card and in its ticket page's Agent section as a `Working` badge with its name, its open tool call and how long its run has lasted, linking to its session, and as a Working row on the Team page; the badge leaves when the subagent stops, its session ends or 600 s pass with no event, and `list_board` names it as the ticket's agent after a claim's holder and a running board run (CF-1184) | Every ticket an agent works on says so, whether a board run or a session subagent does the work |
| The panel is opaque; every property row puts its label left of its field, in a label column as wide as its widest label; at rest a control shows only its value (no arrow, no date mask), and an empty one says what empty means ("none", "not blocked") in light italic, never an example value; a path too long for its field reads whole as the field's tooltip; the agent section carries spend against budget, the repository's monthly budget with the day it runs out at the month's pace (CF-671), and the last stop | Translucency and example values both read as content that is not there; one row layout and one control style read as one column |
| A missing ticket says so on its page, inside the layout (`e2e_a_missing_ticket_says_so`) | A bare error left no way back but the browser's |
| A card's title is a link to the ticket's page: a keyboard reaches it and Enter opens the panel, a middle click or the browser's link menu opens the page in a new tab, a plain click opens the panel, and Cmd, Ctrl or Shift click stays the bulk selection's | A card opened only on a mouse click on a `div`: no keyboard, no new tab (CF-47) |
| The command menu's combobox names the highlighted option in `aria-activedescendant`, after each search and each arrow, and is `aria-expanded` only while options are listed (`CommandMenu.vue`) | A screen reader follows the active descendant, not the options' `aria-selected` (CF-47) |
| A ticket with a branch shows its Changes on its page (the branch tip against its merge base, at most 400 lines), below the ticket's fields and above its Archive and Delete bar: the changed files as a folder tree, a file chosen there taking the keyboard to its diff, and each kept or added line has a comment form of its own, whose comment is recorded as `<file>:<line>: <words>` and so reaches the next agent run's prompt; the panel links to it with Review changes | Reviewing agent work meant leaving the board, and a general comment named no line (CF-169) |
| A card opens the panel for triage; every other ticket link (inbox, archive, Flow, Cmd+K, Copy link, linked tickets) opens the ticket's own page at `/tickets/<repository>/<id>`, which shows the panel's form in page mode | Quick looks stay on the board; reading and sharing get a page without a board behind it |
| Until a page's first answer it shows `Skeleton`s in the outline of its sections (`ReadSkeleton.vue`: a table, cards of a list, a grid of cards, tiles over a chart, or a document) and says "Reading <what>" to a screen reader; the ticket page and panel draw no form meanwhile (`the_ticket_form_shows_loading_until_its_first_answer`); a read that fails says so with "Read again" (`ReadState`) | An empty page reads as broken while the first answer is on its way (CF-487), and a read that never answers must not read as loading for ever |

| An empty section that only waits for work says what brings it: the Inbox (agents ask here when they need you), Sessions (start an agent on a ticket), Team's Working (start an agent on a ticket and it works here) | "Nothing" with no next step left a new owner without a way forward |
| A ticket's Links section, on the page and in the panel, lists its parent, children (with how many are done), blockers and what it blocks, each with its title, its stage and a remove control and linking to the page in its own repository (`linked` in `GET /api/tickets/<repository>/<id>`, whatever repository the linked ticket is in); one Link a ticket control picks a kind and finds a ticket of the same repository by id or title, and a refused link shows its reason in the picker; the picker's search takes focus when it opens, and Link a ticket takes it back when a link is added or the picker is escaped | Children showed only as a count, and a relationship changed only by typing raw ids into a property (CF-253) |

## Frontend rules

The Vue app’s rules and their tests are in [Design](design.md). The ones a
person meets:

| Rule | Reason |
|---|---|
| Every refusal shows: the server's reason in the page's notice or under its item; an Inbox action's refusal shows under its item while the refresh after it still lists the item, else in the page's notice after the item's name (`CF-12 permission: ...`, a rule by its kind, CF-434, CF-435); an answer is announced in the page's notice, an Inbox answer included, and one that says nothing clears the earlier notice; when an Inbox row leaves after its action, focus goes to the row now in its place, else its section's heading, else the page's first heading; Delete on a ticket, and Remove on an agent or a connection, ask first in the one confirmation dialog (`ConfirmDialog.vue`, `lib/confirm.ts`) and say it can be brought back with Undo in the notice that follows | A refused action that showed nothing looked like nothing happened; a refusal shown only in its row left with an item that had already gone, and several in a row could not be told apart |

## Components

The Vue components are shadcn-vue's (`web/src/components/ui`) and the theme's tokens, with the
two shared classes shadcn-vue has no answer for in `web/src/styles/app.css` (`docs/design.md`).
The shell is the page beside a sidebar that folds to icons. The primary colour is one indigo in both themes
(docs/design.md, Theme); otherwise colour is kept for status, stages and labels. A
status word is a `Badge` whose variant carries its meaning: a neutral outline with a dot in the
status colour, red tinted for a failure: `success` for finished, done, approved and merged, `info` for working, running, an open
pull request and checks running, `warning` for waiting, waiting on you, stale, uncommitted and a
conflict, `destructive` for denied, failed and checks failing, `outline` for idle, stopped,
closed, ended, draft and interrupted. A card's delivery chip reads the same map by its words:
`Ship failed`, `Merge failed` and `Checks failed` destructive, `Waiting for an answer` and
`Merge conflict` warning, `Waiting for checks`, `Shipping branch`, `Opening pull request` and a
run info. A page where only what needs the owner carries a colour
(Team) draws the rest on `outline`. Each stage's glyph has a hue of its own and fills as the work
moves, and each label has one of eight colours (`docs/design.md`).

A button is shadcn-vue's `Button` (`web/src/components/ui/button`) and a sidebar entry is
its `SidebarMenuButton`, so a page or component writes no `<button>` and no `btn`
class of its own. `web/src/buttons.test.ts` fails for a new one and for a listed file
that no longer needs its place on the list of files not yet moved. Its helper,
`web/src/test/guard.ts`, is the one helper every guard (`buttons`, `fields`, `states`, `structures`)
reads files and allowlists through.

A menu is shadcn-vue's `DropdownMenu` (or `Popover` for a form), a switch between views or modes
is its `Tabs` or `ToggleGroup`, a disclosure is its `Collapsible` and a table is its `Table`
(CF-1277). `web/src/structures.test.ts` fails for a `dropdown`, `popover`, tab class or tab role,
a radio drawn as a button, a `<details>` or a `<table>` outside them, and for a listed file that
no longer needs its place on its list, each entry with its reason. Line tabs are only the ticket's
content panes; a Markdown field's Write and Preview (a ticket's Description, an agent's Context)
are the default tabs, Write first.

## From the trace viewers, to apply when cost arrives

| Rule | Reason |
|---|---|
| Status is shown only when abnormal; a normal row carries duration alone | Every row glyphed is no row glyphed |
| A second muted line reads `latency · tokens · cost`, absent values omitted | The row set the mature viewers converge on |
| Cost is what the agent runtime reports (a run's `total_cost_usd`, a transcript's `cost-state`), never estimated from a price table the board ships; a ticket's cost is the sum its agent runs recorded, and an interactive session's cost stays on the session, since one session spans many tickets and reports one total (CF-157). A run that reported tokens and no cost is estimated at the price its agent's definition names (`input_price` and `output_price`, dollars per million tokens), 0 for an agent on a connection served on this machine or on the owner's codex login (CF-1320) that names none, and every amount holding such an estimate is led by `~` with a tooltip saying so: the card's and the ticket page's spend (`~$3.25 of $2.50`) and Flow's cost (`~$0.00` for a local agent's runs, the merged table's Cost column too, CF-1316); a run with neither a cost nor a price stays `not reported` (CF-1216) | Silent zeros and unlabelled estimates are the two ways cost displays lie; a day's session cost once showed on whichever ticket its branch matched; a week of local runs used 8 million tokens and showed no cost at all (CF-1216) |
| Errors propagate to ancestors, and a "jump to error" selects the deepest failure | Failures buried in a long run are the ones that cost the most |
